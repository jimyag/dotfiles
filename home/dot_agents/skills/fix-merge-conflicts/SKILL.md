# 解决合并冲突

## 目标

把冲突文件恢复到可构建、可测试、可继续提交的状态。

## 基本流程

1. 先找出所有冲突文件
2. 逐个理解双方改动意图
3. 用最小改动解决冲突
4. 确认没有残留冲突标记
5. 重新执行相关验证
6. 暂存并汇总处理结果

## 处理原则

- 优先保持行为正确，而不是机械选一边
- 能保留双方有效修改时尽量保留
- 不要借冲突顺手做无关重构
- lockfile 优先通过工具重新生成，不手写

## 最小检查

- `git status`
- 搜索 `<<<<<<<`、`=======`、`>>>>>>>`
- 相关测试、构建、lint

## 输出要求

- 哪些文件已解决
- 关键取舍点是什么
- 哪些验证已通过
- 是否还有未解决冲突
