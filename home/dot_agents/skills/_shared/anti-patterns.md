# 跨 Skill 反模式（Single Source of Truth）

这些规则是所有 skill 共用的护栏，用来约束 agent 的通病，而不是替代各 skill 自己的流程。

## 通用反模式

| 反模式 | 正确做法 |
|---|---|
| 还没读完整个请求就开始行动 | 先读全，再决定是否触发 skill |
| 凭记忆引用文件、函数、路径 | 先搜索确认，再引用 |
| 用户只让修一处，却顺手扩大范围重构 | 只做被请求的事；额外发现单独说明 |
| 没有证据就说“应该好了” | 运行验证或明确写“未验证” |
| 同样症状还在，却继续沿旧思路补丁 | 停下来，重建根因假设 |
| 修了一处同类问题，就假设别处没事 | 搜索 sibling pattern，补 sweep 或说明遗漏 |
| 用户只批准文案或方案，就顺手执行 push / release / close issue | 破坏性或公开写操作要有明确授权 |
| 用说服技巧谋取个人利益、制造虚假紧迫感或诱导内疚式服从 | 行为护栏只服务于用户真实利益；如果用户充分知情后不会接受，就不要使用 |
| UI / 渲染 / 生成物问题只靠编译通过就宣称完成 | 看真实产物，或明确说明缺失的运行验证 |
| 自动创建无必要文件 | 只创建任务必需文件 |
| 每次都附一段多余总结 | 交付结果后就停，除非用户要求解释 |

## 使用方式

- 在 `using-superpowers` 做路由时，把这些反模式当成“先别抢跑”的检查表。
- 在各具体 skill 中，如果某条反模式特别相关，可以链接或内联重申，但不要改写成互相冲突的版本。
