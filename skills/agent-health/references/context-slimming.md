# 上下文与技能精简

用户要求精简每轮加载的指令和技能，或者模型升级后要重新校准规则时，按本流程执行。默认只读：先交付清单，用户确认后才改文件。

## 完成标准

- 每轮固定加载的内容（全局规则、项目根规则、没有 `paths:` 的规则、所有技能描述）有前后字数对比。
- 每条消失的行都能对应到用户确认过的一项清单；没有确认的删除一律恢复。
- 一个没参与精简的 Agent 只拿到消失的行和仓库，按关键名词搜索，确认每条的意思都还能在某处找到；找不到的原样恢复。
- 挪到按需加载位置的内容，已用暗号在新会话中验证：读匹配的文件时会加载，读不匹配的文件时不会加载。
- 不可逆操作的规则（删数据、花钱、发布、提权、改写已推送历史）原样保留，或者整段原样搬走。

## 顺序约束

1. 先盘点和清单，用户确认后才改。
2. 先挪再压缩：能整行搬到按需加载文件的整行搬，搬的时候不改写。
3. 先自查（glob 能匹配到真实文件、旧文件名没有残留引用、消失的行全部对上清单），再交给独立复核。
4. 暗号验证完成后删除暗号。

## 清单的判断口径

每条写处理方式（修、删、挪、改写、保留）、目的地和一句原因。

- 删：去掉后行为不变。「先读再改」「跑测试」「注意边界」「遵循周围风格」这类默认行为，口号，以及和技能描述同义的路由句。
- 改写：步骤删掉后还能换一条路达到同样的结果，就只写结果和完成标准；顺序本身是约束的（先验证再发布、先确认再删除、先推 public 再更新子模块）保留顺序。同一要求说了三遍的，用一个概念词加一组 NO / OK 例子合并。
- 挪：只在部分场景才用到的内容挪到技能或 references；需要判断的进技能，输入固定、输出固定的进脚本或 hook，项目命令进项目指南，跨项目的硬约束才留在全局规则。「做 Y 前先读 X」优先改成做 Y 时由 hook 或按路径加载的规则把 X 注入进来。
- 保留：用户偏好、被否决的方案和原因、机器环境、不报错的坑、看起来像出错其实正常的现象、描述里的半句约束（「只读」「不上传」「不自动安装」）、带日期的决策。
- 删除理由是「某处已覆盖」时，逐个要点核对覆盖是否完整：技能里的同义句只在技能加载时可见，描述只覆盖部分触发条件也算覆盖不全。hook 的拦截范围比原规则窄时（例如只拦截 Edit/Write，不拦截 Bash 写入），原规则保留。
- 合并成概念词时，把原来几行里的每个要点逐一放进新定义，不能只留下大意。
- 拿不准的标 `?`，交给用户决定；用户说「按建议改」时，`?` 一律按保守处理，即保留。

## 证据怎么取

- 字数：`wc -m` 统计规则文件；技能描述按 frontmatter 的长度统计。
- 技能有没有人用：看会话原始记录，不 grep 名字（技能列表本身会出现在记录里）。Claude Code 统计 `~/.claude/projects/**/*.jsonl` 中 `tool_use.name == "Skill"` 的 `input.skill`，加上工具参数里读取 `skills/<名字>/SKILL.md` 的次数；Codex 统计 `~/.codex/sessions/**/*.jsonl` 里 `function_call` 参数读取 `SKILL.md` 的次数。同时报告统计窗口和安装日期，零调用的技能要看它装了多久；由 CLI 安装的技能还要看那个 CLI 本身有没有被执行过。
- 消失的行：对旧版本和新文件按行做差集（旧文件中的非空行，新文件里找不到原样的）。不要用 `grep '^-[^-]'` 过滤 diff，那会把以 `- ` 开头的列表行全部漏掉。
- 加载验证：在新文件里埋一个暗号，用 `claude -p "用 Read 读取 <匹配的文件> 的前 5 行，然后逐字列出上下文里所有含『验证暗号』的行，不要用工具搜索" --allowedTools Read` 开新会话；再换一个不匹配的文件做反向对照。

## 已核实的客户端行为（Claude Code 2.1.322，2026-11-11）

升级后先复测这几条，再沿用结论。

- `when_to_use` 会拼进技能描述一起常驻（schema 写的是 "Becomes part of the tool description"），挪过去不省字；Codex 和开放规范都不读它。近义词要么删，要么留在 `description`。
- 项目没有自己的 `CLAUDE.md` 时，Claude Code 读 `AGENTS.md`（已用根目录暗号实测）。根目录不需要 `CLAUDE.md` 软链接；删除前后都用暗号确认根规则仍会加载。
- 子目录的 `AGENTS.md` 会在读到该目录下的文件时作为嵌套指令加载。全局规则的源文件如果放在仓库里（例如 chezmoi 的 `home/dot_agents/AGENTS.md`），读技能文件时它会被再加载一遍；用项目 `.claude/settings.json` 的 `claudeMdExcludes` 排除，并用暗号复测。
- `.claude/rules/*.md` 的 `paths:` 按读到的文件路径匹配，经软链接的路径也会命中。
- Claude Code 的 Edit/Write 会拒绝写软链接；Codex 的 `apply_patch` 不会，需要由 PreToolUse hook 拦截。
- 本机的 link 脚本只给 Cursor 和 Copilot 链接了 skills，没有链接全局规则，所以项目规则里和全局规则重复的句子不删。换了工具组合后重新核对。
