# 代理配置健康检查

## 目标

找出代理工作流里会让后续执行变差的配置漂移：规则冲突、技能触发错误、钩子过宽、MCP 权限不清、验证命令失真、持久上下文过期。

## 何时使用

- 检查 `AGENTS.md`、`CLAUDE.md`、技能、钩子、MCP、代理配置
- 用户觉得 Codex/Claude 没按规则执行
- 新增或迁移一批技能后，需要确认边界是否清楚
- 长期项目里验证命令、生成物规则或上下文文档可能已经过期

## 审计层次

按下面顺序检查，先做概要检查，只有发现高风险或用户要求深入时再扩展：

1. `指令入口`：`AGENTS.md`、`CLAUDE.md`、项目 README、技能头部元数据是否冲突
2. `技能路由`：description/when_to_use 是否过宽、互相抢触发、缺少禁用边界
3. `工具与钩子`：钩子、MCP、允许使用的工具、脚本是否有过宽权限或隐式副作用
4. `验证入口`：测试、静态检查、构建、应用配置、生成物检查是否真实可运行
5. `持久上下文`：计划、交接、记忆、文档是否过期、重复或包含私有路径
6. `可维护性`：是否有重复规则、薄技能、无人维护的脚本、公共/私有边界混乱

## 检查规则

- 证据优先：每个问题必须引用具体文件、命令输出或配置项
- 当前仓库状态优先于记忆和旧总结
- 不把缺少“完美治理”当问题；按项目复杂度校准
- 钩子和自动触发规则要重点看副作用、权限范围和是否可关闭
- 发现敏感信息时只报告类型和路径，不复制具体值

## 输出格式

```text
## 代理健康检查

问题：
- [P0/P1/P2] <问题> - <文件或配置>
  证据：...
  影响：...
  处理：...

正常区域：
- ...

残余风险：
- ...
```

## 严重度

- `P0`：会泄露敏感信息、自动执行破坏性动作、错误发布/提交/部署
- `P1`：会持续误导代理，例如错误验证命令、过宽触发、冲突规则、失效钩子
- `P2`：维护成本或清晰度问题，例如重复规则、过期文档、低价值技能
