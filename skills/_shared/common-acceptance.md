# 通用验收标准（Single Source of Truth）

维护说明：各 skill 直接引用本文件；不要复制后再单独维护。

## 标准版（适用于大多数 skill）

- 输入前提：参数与上下文可解析；缺省参数按 skill 默认值执行，只有默认值会影响结果理解时才在输出中说明。
- 产出要求：覆盖 skill 要求的事实和关键证据（命令、路径、链接或日志摘要），不强制复现模板章节或空字段。
- 通过判定：主流程步骤已完成且无阻塞；实际存在未完成项时，明确标注影响范围与下一步。
- 默认策略（非交互）：可选偏好缺失时采用合理默认值，并在影响结果时说明；必要输入或授权缺失时暂停依赖步骤，继续独立工作。沉默或等待超时不构成同意，已有授权也不需要重复获取。
- 阻塞升级：遇到权限、凭证、外部依赖缺失时立即停止该步骤，输出"阻塞点 + 已尝试 + 需要用户提供的信息"。
- 运行面要求：UI、渲染、生成物、发布链路类任务，默认需要真实产物或运行面检查；仅编译通过通常不够。

## 证据规则（各 skill 引用本节，不各自重写）

- 验证声明：凡是写成“已验证 / 已通过 / 已修复”的结论，都必须有当前会话中的对应证据（命令及其输出、响应、截图、日志或可复现步骤），不得把推断、代码阅读或旧记录写成验证。
- 证据来源分开写：本地验证、远端 CI、线上或集群状态彼此不能替代；每条结论标明来自哪一种。
- 未执行的检查写明名称和原因（缺权限、缺环境、未授权、超出范围），以及它留下的风险；不把“未执行”省略成沉默。
- 证据与对象绑定：结论对应的提交 SHA、PR head、环境或资源 ID 与当前目标一致；目标在验证后变化时，旧证据标为过期并重跑关键检查。
- 输出含糊或部分成功时按失败或未确认报告，附原始输出，不自行解读成通过；没有“部分通过”。
- 交付分档：项目或全局规则定义了交付分档时，验证深度、是否需要运行面检查和独立审查按档位执行，各 skill 不另设门槛。
