## 先沿用已有界面

- 在成熟产品里新增面板、对话框、抽屉、提示或确认框时，方向就是这个产品：先找同类已有组件，复用它的容器、动效和字体变量；要另起风格必须说明为什么没有现有组件适用。
- 新代码动手前对齐：文案语气、颜色及其语义（危险、成功、弱化）、悬停和点击反馈、动效时长和缓动、阴影和卡片处理、密度和留白节奏、圆角规则。换一段内容放进新组件后显得格格不入，说明还没对齐。
- 已有原生应用（macOS、iOS、Android）已经有一致的视觉方向时，不把整体迁移到新的平台风格（如毛玻璃材质、Material You）当作默认改进；默认做间距、对齐、悬停和焦点、字体层级、文案和动效时长的渐进打磨。提改动前用一句话说出现有方向，方便用户纠正。

## 参考来源

- 颜色、字体、宽度和语气依次取自：当前产品的设计变量、同类组件、截图和 git 历史；同一团队的其他已发布产品；对话中的说明。都没有时才使用默认配色和字体。
- 用户给出参考网站或产品（“像 Linear 那样”）时，不把它当方向，提炼三个具体属性：按钮圆角取向、层次表达方式（阴影、背景色阶或边框）、强调色色系。
- 用户提供源码仓库时，读取主题和设计变量文件、全局样式和用户提到的组件，取精确值（色值、间距刻度、字体栈、圆角），不凭记忆重建。只读目标组件目录，不读 `.git`、`node_modules`、`dist` 和锁文件。
- 缺图片、图标或组件时用带标注的占位，不用内联 SVG 画插图或产品图。

## 默认禁用的写法

| 写法 | 改为 |
|---|---|
| 宽于 1px 的左右边框作为强调 | 色点、短横线、背景色块或字重变化 |
| `background-clip: text` 渐变文字 | 纯品牌色、带色相的中性色或字重 |
| 默认使用 `backdrop-filter: blur` 毛玻璃卡片 | 背景色阶加 `box-shadow` 表达层次 |
| 紫到蓝渐变、暗底青色强调 | 根据品牌词选色 |
| 所有内容都套同样圆角加阴影的卡片 | 默认无卡片分区，只在内容类型需要时加卡片 |
| 用模态框兜住普通溢出 | 行内展开、详情面板或独立路由 |
| `transition: all`，或对宽高、内外边距做动画 | 列出具体属性，只动画 `transform` 和 `opacity`；高度展开用 `grid-template-rows: 0fr → 1fr` |

另外检查是否无意中出现：大标题加一行副标题加两个并排按钮的首屏、完全一样的卡片网格、白色与 `#f9f9f9` 交替的分区、四列等权页脚。它们可以出于设计意图出现，但不能是默认结果。换一套完全不同的内容后布局仍然不用改，说明做出的是模板而不是设计。

## 动效

- 先按使用频率决定要不要动：每天触发成百上千次的操作（快捷键、命令面板、快捷键切换标签）不加动效；键盘触发的状态变化不加动效；每天几十次的悬停、列表导航用最短可读的形式；偶尔出现的模态、抽屉、提示用标准处理；一次性的引导和完成时刻可以有点缀。每天都会看到、唯一理由是“好看”的动效删掉。
- 时长参考：按下反馈 100-160ms，提示和小浮层 125-200ms，下拉 150-250ms，模态和抽屉 200-500ms；交互元素超过 300ms 要有理由。感觉慢时先改缓动曲线再改时长。
- 默认用平滑减速（ease-out），不用回弹；只有手指或指针仍在驱动的动作（拖拽关闭、长按）可以有轻微回弹。ease-in 只用于短促的退出。
- 不从 `scale(0)` 进入或退出到 `scale(0)`，从 `scale(0.95)` 配合透明度开始。浮层、下拉和提示从触发它的控件处展开；模态保持居中。
- 可按的元素在按下时要有反馈（如 `scale(0.96)`），不能只有悬停反馈，因为触屏没有悬停。
- 交互状态切换用可中断的 CSS transition；只运行一次的分段入场才用 keyframes。
- 尊重 `prefers-reduced-motion`。

## 可访问性与交互基线

- 只有图标的按钮要有 `aria-label`；动作用 `<button>`，导航用 `<a>`，不用 `<div onClick>`。
- 图片有 `alt`，装饰图用 `alt=""`。
- 焦点可见：不在没有替代样式时写 `outline: none`。
- 可点击目标至少 40×40px，可用居中的伪元素扩大，两个可点击区域不重叠。
- 悬停样式包在 `@media (hover: hover)` 中，避免触屏点按后一直保持悬停态。
- 图片写明宽高防止布局跳动；首屏以下图片懒加载；关键字体用 `font-display: swap`。
- 计数器、计时器、价格和数字列使用 `font-variant-numeric: tabular-nums`。

## 内容真实性

- 示例数据不用 John Doe、Acme Corp、Lorem Ipsum；用有具体感的名字和公司名，写与版面阅读层级匹配的短文案。
- 示例数值不用 99.99%、50%、$100.00 这类整数，改用 99.94%、47.2% 这样的自然值；多个头像不重复同一张图，多张卡片不写同一个日期。
- 成功状态不加感叹号；错误信息不以“哎呀”开头，不写“出了点问题”，写清发生了什么和下一步。
- 首屏和按钮文案不用“赋能”“无缝”“释放潜能”“下一代”等空泛词，写出具体价值。

## 文本与布局

- 不靠 `…` 截断塞进固定宽度：缩短格式、按完整片段截取或硬裁剪；指标和标签页脚不能截成省略号。
- 多出一个词导致换行、最后一行只剩一个词时，先检查容器宽度和强制换行，再在不丢意思的前提下精简重复；不为消除孤词缩小字号。修一处时检查同类区块是否有同样的布局原因。
- 一个小卡片内每种角色只用一种文字样式，靠顺序表达层级；超过三种文字样式说明层级混乱。
- 同一行卡片高度一致，较短的卡片补一行信息而不是补内边距；按钮底部对齐；正文行宽约 65 字符。
- 嵌套圆角满足 外圆角 = 内圆角 + 内边距；动手前先定一组有名字的圆角刻度。
- 间距是一个体系：页面整体太松或太紧时按同一比例缩放整套间距，而不是只调一个间隙。调了多次仍不对称，问题在结构。

## 渲染验证

- 验证渲染结果，而不是类型检查或读 CSS：提前换行、孤立的分隔点、表格溢出只在渲染中可见。
- Web 至少检查 375px（按钮再看 320px）和 1280px，覆盖所有上线语言，在按钮、标签、导航和紧凑卡片中放入长单词和本地化长文本。
- 原生应用检查最小宽度、最小高度、两者组合和常规尺寸。
- 宿主环境无法渲染时说明原因，并把需要用户检查的具体视图交给用户。

## 提供选项

- 用户要选项时至少给 3 个，在密度、字体性格、色温、布局结构、动效性格、装饰程度等不同维度上拉开差异：一个贴近现有约定，一个重新组合品牌元素，一个刻意出人意料。只换强调色不算三个选项。
- 图标、字重、强调色、动效手感这类口味问题，即使用户没要求，也给两个标好名字的候选，让用户回一个字母即可；结构性改动先用一两句话描述最终效果，得到确认再写代码。

## 交付前自查

- 第一屏能否明确看出品牌或产品？是否有一个真实的视觉焦点，而不是装饰性渐变？
- 只看标题能否理解页面？每个分区是否只做一件事？卡片是否真有必要？
- 动效是在强化层级或氛围，还是纯装饰？去掉所有装饰性阴影后是否仍然成立？
- 陌生人扫一眼第一屏，会不会觉得“这是 AI 做的”？会的话，回到上面的禁用写法和常见模板逐项修正。
- 404、返回路径、表单校验、跳到主内容链接、Cookie 同意、隐私与条款链接只作为遗漏提醒报告；视觉打磨请求不授权新建这些页面或流程。
