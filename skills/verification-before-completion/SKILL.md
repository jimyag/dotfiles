# 完成前先验证

## 最小流程

1. 定义能证明当前目标成立的最小检查。
2. 在本次改动后执行检查并读取输出、退出码或真实产物。
3. 根据实际覆盖范围决定结论强度；局部检查只能支撑局部结论。
4. 未执行或无法执行的验证，明确写出缺口和影响。

## 输出要求

- 验证：执行的命令或检查，以及结果。
- 未验证：缺失项及原因。
- 结论：只陈述当前证据能支持的范围。

## 关键约束

- 旧结果和推断不算本次验证证据。
- UI、渲染、生成物和发布链路需要检查真实运行面；编译或单测通常不够。
- 涉及 generated artifact、release asset、version 或 changelog 时，验证其同步状态。
