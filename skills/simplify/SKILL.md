# 简化代码

在完全保留功能的前提下简化代码。优先选择易读、行为明确的写法，而非紧凑或巧妙的写法。

## 边界

- 已有失败或异常行为先用系统化调试定位；本技能不把修缺陷伪装成等价重构。
- 需要改变功能、API、错误语义或兼容行为时停止，并将它作为单独变更讨论。
- 默认只处理当前任务或会话中的改动，遵守项目指令并保留工作区中的无关改动。

## 流程

1. 确定用户要求的范围、最近修改的代码，以及能证明现有行为的测试、命令或可观察结果。
2. 阅读适用的项目指令和相邻代码约定。
3. 找出具体的降复杂度或提高清晰度机会。候选较多或取舍不清时阅读 [清晰度检查](references/clarity-checks.md)。
4. 做保持行为不变的最小改进。
5. 检查差异，逐项确认没有改变控制流、错误行为、输出、副作用、并发顺序或兼容边界。
6. 使用修改前的同一行为入口验证，再按风险补充更宽检查。
7. 只报告重要改进和验证缺口。

无法建立行为基线时，只做可以由静态等价直接证明的局部简化，并报告未验证边界。验证失败、差异显示行为变化或需要猜测原意时，停止本轮简化并恢复本轮未成立的改动，不用“代码更短”作为成功依据。

## 输出

- 简化了什么复杂度，以及为什么行为保持不变；
- 实际执行的行为基线和验证结果；
- 没有执行的运行面及其影响；
- 没有安全简化机会时，明确说明保持现状。
