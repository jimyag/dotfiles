# 查找可用技能

## 目标

根据用户需求，从现有技能生态里找出可能适合的技能，并给出是否值得引入的建议。

## 何时使用

- 用户问“有没有技能能做这个”
- 用户想扩展代理能力
- 用户想找某类工作流、工具或模板

## 基本流程

1. 先明确用户要解决的具体问题
2. 提炼关键词
3. 用 `npx skills find <query>` 搜索
4. 对候选技能做安全与适配检查
5. 给出候选技能，并说明用途与取舍

## 常用命令

```bash
npx skills find react performance
npx skills find pr review
npx skills find changelog
```

## 输出要求

- 说明技能名称
- 说明它解决什么问题
- 说明是否建议引入
- 如果适合本仓库，优先建议将源码纳入仓库，而不是直接全局安装

## 安全与适配检查

外部技能不能只看 README 或收藏数。建议引入前至少检查：

- `SKILL.md`、头部元数据、允许使用的工具、钩子、MCP 配置和脚本入口
- 是否有提示词注入、数据外传、读取敏感目录、执行远程脚本、自动提交/发布/删除等高风险行为
- 是否声明过宽权限，例如能读写全盘、调用网络、执行命令行，但工作流实际不需要
- 是否会把私有路径、令牌、会话 Cookie、邮箱、SSH 配置或公司内部信息写入持久文件
- 是否和本地已有技能重叠；能抽一条规则合入现有技能时，不新增整套工作流

## 关键约束

- 不要只给安装命令，不给判断
- 不要为了“有技能”而推荐低价值技能
- 找不到时就明确说没有合适候选
- 没完成安全与适配检查时，不要建议全局安装或自动启用钩子
