# 受控技术说明

用于操作手册、API 流程、故障处理和安全说明。

## 编写规则

1. 将执行前必须知道的条件、权限、风险和停止条件放在动作之前，并写清条件是必要还是充分：条件满足后才允许执行时写“只有检查通过，才允许重启”，条件满足就要执行时写“检查通过后，重启服务”。
2. 一个编号步骤只保留一个主要动作，并写清执行者、对象和成功信号。依赖前一步结果的动作写明完成条件，例如“上传完成后，删除本地文件”；只给有先后关系的动作编号，可选项写成并列分支。
3. 区分人工操作与系统自动行为；写出可观察结果，而不是只写“执行成功”。
4. 故障排查先安排低风险、可逆、证据价值高的检查，再根据结果选择恢复动作。
5. 将现象、证据、可能原因、恢复操作和验证分开，不把推测改成事实。
6. API 参数覆盖类型、是否必填、单位、默认值、允许范围、缺省行为和依赖关系。
7. 删除、覆盖、迁移、发布和权限修改写清备份、回滚与不可逆边界。
8. 区分要求、建议和允许；“否则”分支写清判断的是没有执行还是执行未成功，“自动恢复未成功时通知值班”与“未开启自动恢复时通知值班”是两个条件。

状态文案按实际语义翻译，不逐词映射。命令、路径、字段、配置项和错误原文保持不变。
