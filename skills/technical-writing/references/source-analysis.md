# 源码分析模式

## 证据顺序

1. 确认源码来源、版本、提交和构建条件；用户要求最新状态时重新获取或验证。
2. 从真实入口与调用方开始，沿关键类型、字段、函数、状态转移和失败路径展开。
3. 用代码位置支持事实，用运行或测试支持行为；不要用概念介绍替代实现。
4. 对并发、网络、调度和状态机使用必要的 Mermaid 或 ASCII 图，并写明省略内容。
5. 区分源码事实、文档事实、基于事实的推论和个人建议。
6. 补充边界行为、常见误解、生产注意事项和可重复实验。

## 深度判断

如果文章仍然可以不看源码就写出来，通常还不够深入。用户指出“太浅”时，回到入口、数据结构和调用链重建文章，不在概念段落后机械追加细节。

不能运行源码或实验时，明确说明哪些行为仅由静态阅读推断。编译通过不能证明运行时状态、并发顺序或性能结论。
