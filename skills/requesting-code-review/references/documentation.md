# Documentation Accuracy lane — 检查要点

## 行为变更文档同步

- 修改了函数/接口/配置的行为，对应文档、注释、示例是否同步更新
- 删除或重命名了公开符号，是否通知了调用方（迁移说明、CHANGELOG）
- 改变了默认值或错误返回，是否在文档中标注
- 修改字段名、分页参数、筛选条件、枚举值、返回结构或错误码时，是否同步到客户端、调用方示例和接口文档
- 兼容性变化是否说明旧调用方、旧数据和升级路径的影响

## 过期注释与示例

- 注释描述的行为是否仍和当前实现一致
- 示例代码是否仍可运行（参数名、返回值、API 签名是否匹配）
- 注释中引用的外部链接或内部路径是否仍有效

## 公开接口文档缺失

- 新增或改动的公开函数/方法/类型/端点是否有文档（godoc、docstring、OpenAPI 等）
- 参数、返回值、错误码是否描述准确完整
- 用户可见的错误信息是否清晰可操作

## 用户/运维文档缺失

- 新增的配置项是否有文档（用途、类型、默认值、约束）
- 新增的 CLI flag 或环境变量是否有说明
- 影响部署、升级、回滚的变更是否有对应操作说明
- 新增或修改配置时，默认值、样例配置、注释、环境变量和部署说明是否一起更新
- 没有配置、旧配置升级、新环境部署时的行为是否清楚且和文档一致
- 环境差异是否显式写成配置或部署说明，而不是只藏在代码分支里

## 代码与文档不一致

- 文档中声称的行为（如"幂等"、"线程安全"、"最多重试 N 次"）是否与实现一致
- 配置文件中的注释与代码中的实际读取逻辑是否一致
- README 中的使用示例是否与当前 API 签名一致
- 服务端、客户端 SDK、OpenAPI/接口文档、前端调用和示例中的字段名、枚举大小写、默认值是否一致

## 判断原则

- 优先关注用户/运维会直接依赖的文档（对外 API、配置说明、错误信息）
- 内部注释过期但不影响外部行为时，酌情降优先级
- 不要求每行代码都有注释，只关注行为和文档之间的真实不一致
