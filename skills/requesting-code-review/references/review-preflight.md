# Review 范围与完整性预判

## 目标与需求

- 将改动标记为 `目标一致`、`范围漂移` 或 `不完整`。
- 有关联 issue、ticket 或 PRD 时，提取需求、验收标准、非目标和人工验证项，再对照 diff。
- 没有关联需求时，只使用 PR 描述、提交信息和 diff，不臆造目标。
- 仅当多个主题没有代码依赖、能独立 review/merge 且拆分能降低真实风险时建议拆分。

## 完整性

- 模式修复要搜索 sibling pattern，并区分同类问题、安全例外和待确认项。
- 检查契约是否同步到调用方、配置、文档、生成物和验证证据。
- 生产路径新增 I/O、重试、队列、后台任务或跨服务调用时，检查日志、指标和错误语义。
- 安全边界、权限、 destructive path、迁移和兼容策略缺失时提升优先级。

## 双轴与反证

- `需求轴`：目标、范围、兼容性、生成物、文档和验证是否完整。
- `工程轴`：正确性、可维护性、性能、安全、测试和项目约定。
- 每个非平凡 finding 写清主张、成立约束和可能反例；找不到可验证主张时降级为待确认。
- 输出前寻找能直接推翻 finding 的当前 diff 或上下文证据，存在反证时删除。
