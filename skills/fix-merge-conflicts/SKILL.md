# 解决合并冲突

## 目标

按用户要求的完成边界解决冲突并验证；已授权完成的合并、变基或 cherry-pick 应推进到操作结束。

## 基本流程

1. 检查 `git status`，找出所有冲突文件、正在进行的 Git 操作和用户要求的完成边界
2. 逐个理解双方改动意图
3. 用最小改动解决冲突
4. 确认没有残留冲突标记
5. 重新执行相关验证
6. 按授权范围暂存已解决的目标文件，并检查是否仍有未解决文件
7. 用户已要求完成当前合并、变基或 cherry-pick，或该操作是已授权流程的必要步骤时，继续相应 Git 操作并处理后续冲突，直到操作结束
8. 核验最终 Git 状态，汇总结果及仍未完成的事项

## 处理原则

- 优先保持行为正确，而不是机械选一边
- 能保留双方有效修改时尽量保留
- 不要借冲突顺手做无关重构
- lockfile 优先通过工具重新生成，不手写
- 仅要求修复冲突文件，或明确要求停在文件修改、暂存状态时，保留该停止边界；仓库存在进行中的 Git 操作本身不构成继续操作的授权
- 使用本技能不自动授权推送或改写远端历史；继续 Git 操作时仍保护与当前任务无关的改动

## 最小检查

- `git status`
- 搜索 `<<<<<<<`、`=======`、`>>>>>>>`
- 相关测试、构建、静态检查

## 输出要求

- 哪些文件已解决
- 关键取舍点是什么
- 哪些验证已通过
- 是否还有未解决冲突
- Git 操作是否已结束；若停在文件修改或暂存状态，说明对应的用户要求
