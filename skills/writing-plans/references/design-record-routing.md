# Design Doc 与 ADR 路由

只有决策会长期约束实现、选错代价高或需要多人在实现前达成共识时，才增加文档流程。

## Design Doc

满足以下任意两项时，建议先补设计文档：复杂或高风险；跨团队；长期运行且回滚昂贵；涉及接口、数据、权限、存储、部署、兼容性或外部依赖；reviewer 需要实现前确认目标和备选。

## ADR

满足以下任意两项时，建议用 `architecture-decision-record`：比较过真实备选；接受非平凡成本；决策难回滚或约束后续设计；未来维护者需要理解为什么。

低成本、可随实现调整的细节不需要 Design Doc 或 ADR。
